# Ralph на Codex SDK

Отдельный пакет, не использует и не изменяет `tools/ralph`.
Нужны Node.js 22+, Git, авторизованный `gh`, доступ к Codex
(`codex login` или `OPENAI_API_KEY`) и окружение проекта для `make check`.
Используется официальный [`@openai/codex-sdk`](https://developers.openai.com/codex/sdk/).

```sh
cd tools/ralph-sdk
npm ci
npm run once -- 18
npm run ralph -- 18 42
```

`once` выполняет одну попытку и оставляет изменения для ручной проверки.
`ralph` обрабатывает указанные задачи последовательно: попытка → ревью →
доработка → повторное ревью → коммит → комментарий в issue.
Скрипт не пушит, не закрывает задачи и не создаёт PR.

## Попытка

`lib/attempt.ts` получает задачу и Codex, возвращает
`{ threadId, checkOk, fixes, report, usage }`. `report` содержит `summary` и `files`.
Оба запуска используют одну реализацию, печать событий вынесена в `lib/log.ts`.

Заголовок и описание загружаются через `gh issue view --json`.
Исполнитель работает в корне Git с `workspace-write`, `approvalPolicy: never`
и моделью из настроек Codex. Поток событий печатает короткие команды,
коды выхода и изменённые файлы; полный stdout сохраняется в логах проверок.
Агенту запрещено запускать `make check`, Ralph, коммитить и менять GitHub.

После хода сам раннер выполняет `make check`. При сбое он передаёт последние
120 строк (до 24000 символов) исполнителю в том же потоке. Разрешены два
исправления, затем незелёная проверка останавливает задачу без коммита.
Та же проверка выполняется после доработки замечаний ревью.

## Ревью и завершение

Каждое ревью получает отдельный `startThread` с `read-only` и reasoning `high`.
Ответ проверяется Zod-схемой `{ findings: [{ priority, file, line, text }] }`,
переданной как `outputSchema` через `zodToJsonSchema(..., { target: "openAi" })`.
Для конвертера используются совместимые схемы `zod/v3` из установленного Zod 4.
Наличие P0/P1 определяет код. После первого отказа все P0/P1 целиком
передаются через `resumeThread` исполнителю с прежними опциями. Максимум —
два раунда ревью. P2/P3 не блокируют коммит и перечисляются в комментарии.

При одобрении скрипт выполняет `git add -A`, исключая `.ralph`, затем коммит
`<заголовок задачи> (#N)` с `summary` в теле. Новая задача требует чистой
рабочей копии. После остановки правки остаются; следующая новая задача
также остановится, если рабочая копия не чистая.

Комментарий через `gh issue comment --body-file` содержит результат,
файлы, число раундов, открытые замечания с файлами и строками и токены.
При остановке добавляется причина. Итоговая строка каждой задачи:
номер, `commit`/`stopped`, раунды, токены, хеш. Exit 0 — только если все
задачи закоммичены и комментарии опубликованы.
Причина остановки также печатается в stderr после итоговой строки.

## Ограничения и восстановление

| Переменная               | По умолчанию  | Назначение                                         |
| ------------------------ | ------------- | -------------------------------------------------- |
| `RALPH_REVIEW_MODEL`     | `gpt-6-astra` | Модель ревьюера                                    |
| `RALPH_MAX_TOKENS`       | `3000000`     | Сумма input + output всех завершённых ходов задачи |
| `RALPH_TURN_TIMEOUT_MIN` | `20`          | Таймаут каждого хода через AbortController         |

Cached input уже входит в input и повторно не суммируется. SDK сообщает usage
при `turn.completed`; незавершённые ходы не дают точного счётчика расхода.
Лимит проверяется до следующего хода и после каждого полученного usage.
При превышении бюджета или таймауте задача останавливается с комментарием,
обработка очереди продолжается.

После каждого шага `.ralph/state-N.json` атомарно сохраняет `issue`, `stage`,
`round`, `workerThreadId`, `tokens`, `findings`, а также отчёт и позицию внутри
попытки. При повторном запуске этап продолжается, проверка чистоты пропускается,
существующие потоки восстанавливаются через `resumeThread`. Этап `check`
не повторяет уже завершённый ход. Прерванное ревью восстанавливает свой поток;
следующий раунд создаёт новый. Перед коммитом сохраняется HEAD, чтобы
восстановление после коммита не создало второй коммит.

После финального комментария состояние удаляется. Если GitHub недоступен,
состояние остаётся на этапе `comment`: повторный запуск повторяет публикацию,
не работу агента. При аварии между публикацией и удалением состояния возможен
повторный комментарий. `.ralph/` исключена из Git.

Если остановка уже опубликована, файл состояния удалён: обычный повторный
запуск считает задачу новой и требует чистой рабочей копии. Для ручного
продолжения после успешного `make check` можно восстановить
`tools/ralph-sdk/.ralph/state-N.json` из
`tmp/ralph-sdk/issue-N/attempt-0/result.json` (пути относительно корня Git):
`issue: N`, `stage: "review"`, `round: 0`, `workerThreadId: result.threadId`,
`tokens: result.usage.input_tokens + result.usage.output_tokens`, `findings: []`,
`report: result.report`. Это подходит, если `result.checkOk === true`, ревью
ещё не завершалось, других завершённых ходов не было, а проверенные изменения
сохранены в рабочей копии. После этого `npm run ralph -- N` из каталога пакета
начнёт ревью, сохранив поток исполнителя для возможной доработки. При одобрении
раннер автоматически создаст коммит и опубликует комментарий, как обычно.

Артефакты `once`: `tmp/ralph-sdk/issue-N-*/thread.json`, `check-*.log`,
`result.json`. У `ralph`: `tmp/ralph-sdk/issue-N/<этап>-<раунд>/` и
`tmp/ralph-sdk/comment-N.md`. Историю потоков хранит Codex.
`once` всегда создаёт новую попытку; автоматическое восстановление есть у `ralph`.

```sh
npm test
npx tsc --noEmit
```

Эти проверки не обращаются к модели и GitHub. Полный `ralph` запускается
отдельно, поскольку создаёт коммиты и комментарии.
