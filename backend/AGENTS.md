# Правила работы с backend

Действуют для всего каталога `backend/` вместе с [общими правилами](../AGENTS.md).

## Структура и контракты

- `api/` — HTTP API, `worker/` — обработчик фоновых заданий, `linkprocessing/` — общий Go-модуль обработки ссылок, `migrations/` — встроенные SQL-миграции. Модули объединены корневым `go.work`.
- При изменении API сверяться с контрактами в [api/registration.md](api/registration.md), [api/login.md](api/login.md) и [api/library.md](api/library.md), если они относятся к задаче.
- При изменении HTTP-контракта обновлять аннотации маршрутов и генерировать документацию командой `make openapi`. Сгенерированные файлы находятся в `backend/api/docs/`.

## База данных

- Соблюдать [правила миграций](migrations/README.md): не менять и не удалять применённые миграции, не вставлять новые перед последней применённой. Изменение схемы оформлять следующим SQL-файлом с большим номером.
- Миграции применяет API до запуска HTTP-сервера. Worker не должен применять их самостоятельно.
- Для интеграционных тестов использовать отдельную тестовую PostgreSQL из `compose.test.yaml` и `TEST_DATABASE_URL`, а не рабочую базу. При прямом запуске `go test -tags=integration` задавать `TEST_DATABASE_URL` явно.

## Проверка изменений

- Форматировать изменённые Go-файлы с помощью `gofmt -w <путь.go>`.
- После изменения Go-кода запускать тесты и статический анализ модулей:

  ```sh
  go test ./backend/api/... ./backend/worker/... ./backend/migrations/... ./backend/linkprocessing/...
  go vet ./backend/api/... ./backend/worker/... ./backend/migrations/... ./backend/linkprocessing/...
  ```

- Изменения работы с БД, миграций и взаимодействия API с Worker проверять интеграционными тестами: `make test` поднимает тестовую PostgreSQL и запускает тесты всех Go-модулей с тегом `integration` без кеша. Для запуска нужен Docker.
- `make test-integration` запускает интеграционные тесты только API и требует предварительного `make test-db-up`; он не заменяет полный прогон при изменениях Worker или общих модулей.
