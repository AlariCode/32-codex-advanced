# Правила работы с web

Действуют для всего каталога `web/` вместе с [общими правилами](../AGENTS.md).

## Команды проверки

Команды выполняются из корня репозитория:

- ESLint: `npm run lint --prefix web`.
- TypeScript: `npm run typecheck --prefix web`.
- Production-сборка: `npm run build --prefix web`.
- Playwright: `npm run test:e2e`.
- Сквозные интеграционные тесты: `npm run test:e2e:integration`.

## Обязательная проверка изменений фронтенда

После любого изменения фронтенда выполнить следующие шаги в указанном порядке до завершения задачи:

1. **Визуально проверить интерфейс на нескольких разрешениях.** Открыть измененные страницы в браузере как минимум на мобильном (375 × 812), планшетном (768 × 1024) и десктопном (1440 × 900) разрешениях. Проверить верстку, переносы текста, отступы, переполнение, перекрытие элементов, доступность кнопок и форм, а также основные состояния измененных компонентов. Если изменение затрагивает адаптивные брейкпоинты, дополнительно проверить ширины рядом с ними. Исправить обнаруженные проблемы и повторить проверку.
2. **Провести UX-ревью с помощью установленного скилла `ui-ux-pro-max`.** Прочитать `.agents/skills/ui-ux-pro-max/SKILL.md` в корне репозитория и применить его к измененному интерфейсу после визуальной проверки. Оценить понятность сценариев, навигацию, обратную связь, состояния загрузки, ошибок и пустых данных, доступность и удобство на мобильных устройствах. Исправить выявленные проблемы и повторно проверить затронутые сценарии.
3. **Написать или обновить Playwright-тесты.** Хранить тесты в отдельной папке `web/tests/e2e/`. Покрывать измененное поведение и основные пользовательские сценарии, включая значимые ошибки и регрессионные случаи. Для изменений только верстки добавить или обновить проверки отображения и доступности элементов на затронутых разрешениях. Тесты должны быть воспроизводимыми и пригодными для последующего регрессионного запуска; необходимые настройки и команда запуска должны быть сохранены в проекте. Запустить тесты и исправить ошибки до завершения задачи.
4. **Записать видео Playwright-тестов нового функционала.** Для новых пользовательских сценариев включить запись видео всех соответствующих тестов, включая успешные прогоны (`video: 'on'`). Сохранить видеозаписи во временной папке `tmp/playwright/videos/` в корне проекта; при необходимости настроить вывод артефактов Playwright в эту папку. Проверить, что видео созданы и демонстрируют работу нового функционала. Временные артефакты не коммитить.

В итоговом сообщении указать проверенные страницы и разрешения, результат UX-ревью, команду и результат запуска Playwright-тестов, а для нового функционала — пути к видеозаписям. Если проверка недоступна из-за окружения, явно сообщить, что осталось непроверенным и почему; не считать такую проверку выполненной.
