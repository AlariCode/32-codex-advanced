Управляемые UI-сбои используют mock API. Интеграционные сценарии используют
настоящие API, worker и PostgreSQL; сеть прерывается на браузерной границе.
Потеря ответа после commit воспроизводится `route.fetch()` с проверкой 201,
после чего ответ браузеру прерывается. SQL-проверка считает карточки и задачи
этого владельца, включая завершённые задачи.

Все новые сценарии выполняются на 375×812, 768×1024 и 1440×900.
Конфигурации Playwright записывают видео успешных и неуспешных прогонов.
Артефакты остаются в `tmp/playwright/videos/ui/` и
`tmp/playwright/videos/integration/`. Отдельные каталоги сохраняют записи обоих
наборов при последовательных и повторных запусках.

## Визуальная и UX-проверка

Библиотека `/` (ввод, предварительные карточки и неизвестный исход отправки), читалка `/links/<id>`
(ошибка и повтор): проверены на 375×812, 768×1024, 1440×900.
Горизонтальное переполнение, перекрытия и недоступные элементы не обнаружены.
UX-ревью по ui-ux-pro-max: ошибки объявляются через role=alert, у сетевых
ошибок есть явное действие восстановления, неизвестный исход не выглядит
подтверждённым сохранением, недоступность localStorage сообщается отдельно.
Состояние проверки history snapshot также проверено визуально: до ответа
о сессии приватные карточки и ввод скрыты. Основная навигация и формы
входа/регистрации проверяются регрессионным набором.

## Команды

- `make check` — обычные тесты, go vet, ESLint, TypeScript.
- `make test` — полный набор Go, включая тестовую PostgreSQL.
- `npm run test:e2e` — полный UI-набор на трёх разрешениях.
- `npm run test:e2e:integration` — весь интеграционный e2e-набор.
- `make build` — API, worker и production Web.

## Результаты проверки

- Полный UI-набор: **267 passed**, все три разрешения.
- Отдельная проверка максимального архива на реальной БД:
  `go test -tags=integration ./backend/worker/internal/worker -run '^TestMaximumImageArchivePublication$' -count=3 -v` — **3 passed**.
- При первом полном интеграционном прогоне два сценария `partial illustrated archive: total`
  (mobile, desktop) не дождались публикации worker. Причина не установлена:
  сообщения PostgreSQL не показали SQL-ошибки; лог worker дополнен причиной ошибки
  публикации. Эти сценарии повторены по два раза на каждом разрешении вместе с
  проверкой возврата к отсутствующей статье — **12 passed**, без увеличения таймаутов
  и изменения критериев. Затем запускается повторный полный интеграционный набор.
