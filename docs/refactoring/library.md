# Разделение LibraryPage

## Задача и границы

`library-page.tsx` (804 строки) объединяет состояние сессии, загрузку и polling,
действия пользователя, черновики и разметку. Разделить обязанности внутри
слайса `library`, сохранив публичный API, DOM, CSS, тексты и поведение.
Существующие изменения Makefile, README.md и `.ignore` не затрагивать.
Тесты, фикстуры и конфигурацию не менять.

## Единственный самостоятельный шаг

- [x] Выделить состояние и сброс сессии в `model/use-library-state.ts`,
      загрузку/polling в `model/use-library-sync.ts`, действия в
      `model/use-library-actions.ts`; разметку карточек, приветствия и формы —
      в именованные компоненты `ui/`. Оставить в `LibraryPage` композицию страницы.

Инварианты: порядок хуков и эффектов, отмена запросов, защита владельца,
монотонные часы, поколения повторной обработки, интервалы polling,
localStorage, фокус, пагинация, URL и aria-атрибуты остаются прежними.
Приёмка: полный набор проверок до/после, визуальная проверка `/` на
375×812, 768×1024, 1440×900, UX-ревью; неизменные тесты и CSS.
Перед изменением сохранить исходный компонент в `tmp/refactoring-library/`.

## Журнал

- Исходный запуск из sandbox не получил доступ к Docker socket; повторён
  с разрешениями окружения. Это не ошибка приложения.
- Baseline: `make test-db-up`, `make check`, `make test-integration` — PASS;
  `npm run test:e2e` — 273/273, 3.7 минуты.
- После извлечения ESLint стал анализировать прежний код точнее: ссылки на
  изменяемые значения получили явный суффикс `Ref`, стабильные зависимости
  эффекта перечислены явно. Для прежнего синхронного сообщения об ошибке
  localStorage и чтения ref-снимков при рендере оставлены локальные пояснённые
  исключения правил React; время обновлений и модель состояния не менялись.
- Промежуточные lint/TypeScript использованы для диагностики границ хуков;
  до итогового полного прогона `make check` зелёный.
- Итоговые `make test-db-up`, `make check`, `make test-integration` — PASS.
  `npm run test:e2e` — 273/273, 3.1 минуты; production-сборка прошла
  внутри Playwright webServer. После восстановления сгенерированного
  `next-env.d.ts` к исходному виду `make check` также PASS.
- Визуально проверена `/` на 375×812, 768×1024, 1440×900: пустое состояние,
  обработка, готовая статья, ошибка и невалидный черновик. Все 15 пар снимков
  совпали пиксель в пиксель; горизонтального переполнения нет.
- UX-ревью по `ui-ux-pro-max`: сохранены подписи полей, подсказки, статус
  отправки/обработки, inline-ошибка с исправлением URL, фокус черновика,
  повторная попытка и ссылки на статью/оригинал. Регрессий не обнаружено.
- AST-сравнение подтвердило неизменность тел `load`, `revalidate`, `discover`,
  `refresh`, `send`, `retry`, `submit`, `more`, `openCard` после нормализации
  переименованных refs. CSS и публичный API слайса не менялись.
- Исходники, снимки и логи: `tmp/refactoring-library/`; видео полного прогона:
  `tmp/playwright/videos/ui/`. Временные артефакты не входят в изменения.

- Финальная приёмка: контрольные суммы всех файлов `web/tests/` совпали;
  конфигурация проверок и предыдущие изменения пользователя сохранены.
  `git diff --check` — PASS. Шаг завершён.
