## #10 — Сохранять изображения из relative/lazy/srcset (2026-10-21)

Сделано: img получает ограниченные worker-only Candidates; приоритет

каждый итоговый URL и redirect проходит прежние DNS/SSRF/IP-pinning проверки.
Подписи, alt, порядок исходных позиций сохраняются; первый доступный
проверенный вариант даёт ровно один image. Source/Candidates удаляются после
архивирования и никогда не сериализуются.

Поиск ограничен 8 кандидатами на позицию, 64 записями srcset на атрибут,
100 попытками на статью и прежним общим deadline. Разбор srcset ленивый,
без выделения массива для всех записей недоверенного атрибута. Бюджет
20 MiB теперь учитывает также битые/неуспешные ответы и повторы; production
FetchImageBudget читает не больше остатка/5 MiB плюс контрольный byte.

префикс с Truncated. Пригодный результат получает html_truncated и понятное
