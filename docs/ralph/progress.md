## 2026-10-19 — автоматическое разрешение конфликтов слияния в Ralph

- По запросу пользователя добавлен отдельный запуск Codex при конфликте
  слияния `issue-N` в ветку фазы. Агент объединяет изменения; раннер добавляет
  конфликтные пути в индекс, повторяет настроенные проверки, завершает merge

  с сохранением рабочей копии и открытым issue. Другие ошибки merge не вызывают
  Codex. Пустое содержательное разрешение merge допустимо при зелёных проверках.
- Проверки: 44 теста Ralph прошли, включая настоящие конфликты и push

## 2026-10-19 — продолжение сессии Codex после красных проверок

- По согласованному плану первый запуск остаётся `codex exec`, а возвраты
  после ошибки внешних проверок или коммита выполняются через `exec resume`.
  ID читается из первого корректного `thread.started`; флаги sandbox,
  Go-кэша и JSON-отчёта явно передаются перед `resume` на каждом вызове.
- Обязательный `maxFixAttempts` равен 3. Каждый возврат получает шаблон
  `ralph-fix.md` с последними 80 строками отдельного лога проверки/коммита.
  При потере ID или ошибке команды resume допустим один запуск с нуля
  в рамках того же возврата; причина и результат записываются в `run.log`.
  Повреждённый отчёт остаётся ошибкой, статусы blocked/failed сохраняют смысл.
- Артефакты нумеруются отдельно для каждого вызова, включая неудачный resume
  и fallback. Конфигурация, dry-run, цикл задачи, merge и часть Git/GitHub
  вынесены в небольшие модули; все файлы `tools/ralph` не превышают 150 строк.
  Семантика checks, Git/GitHub и JSON-отчёта сохранена. `.codex/` не менялась.
- Проверки: 75 тестов Ralph, `make check` и строгая проверка TypeScript

## #9 — исправление P1 после код-ревью (2026-10-20)

Причина: protect(img) создавал p внутри исходного p, а structured узнавал
первый маркер по codeText всего предка. Для абзаца, начинающегося с img,
восстановление первого изображения заменяло весь абзац: соседний текст,
следующие изображения и их индивидуальные placeholders терялись.

Исправлено: изображения защищаются inline span с отдельным текстовым токеном.

разворачивания span или слияния текстовых узлов Readeck. Блочный placeholder
теперь принимается только при точном совпадении единственного прямого
текстового потомка; предок с дополнительным содержимым не заменяется.
Буквальный текст с похожим префиксом также сохраняется и не маскирует
следующий настоящий маркер.
