# Ralph Loop

Раннер выполняет последовательные GitHub issues выбранной фазы. Требуется
Node 22.18+ (проверено на 22.19), git, gh с авторизацией, Codex CLI, Go
и окружение для команд проверок, включая Docker для `make test`.

Перед запуском закоммить изменения инструментов и убедись, что рабочая копия
чистая. Настройки находятся в `tools/ralph/ralph.config.json`:
`{phase}` подставляется в метку и ветку; проверки задаются массивами аргументов,
без shell-интерпретации. Значения по умолчанию: `phase-2`, `ralph/phase-2`
для фазы 2; remote — `origin`, базовая ветка — `main`.

```sh
node tools/ralph/ralph.ts --phase 2 --dry-run
node tools/ralph/ralph.ts --phase 2 --max-iterations 10
make ralph PHASE=2
node --test tools/ralph/*.test.ts
```

Dry-run читает Git и GitHub, показывает задачу и условный план команд,
не создаёт файлов и не запускает агента. Лимит считается по задачам:
единственная повторная попытка не расходует дополнительную итерацию.
При достижении лимита с оставшимися подходящими задачами PR не создаётся.
При отсутствии подходящих задач PR может содержать частичную фазу;
заблокированные задачи остаются открытыми. Без коммитов относительно main
создание PR пропускается.

Артефакты: `.ralph/runs/<timestamp>-<pid>/run.log` и подкаталоги `issue-N/`:
`prompt.md`, `events.jsonl`, `report.json`, `check.log`, `agent.log`,
`report.schema.json`. Перед повтором файлы первой попытки сохраняются
в `attempt-1/`; `check.log` содержит проверки обеих попыток.
Журнал знаний `progress.md` находится под Git и коммитится вместе с задачей.

Агент работает неинтерактивно: решения и неоднозначности разрешает
самостоятельно по приоритетам источников из `implement`. Фиксирует допущения
и обоснования в журнале и отчете; отсутствие согласования не является блокером.
При объективной невозможности продолжить возвращает `blocked` с объяснением.
Скиллы подготовки PRD, исследования и планирования в цикле не вызываются. Обязательные
визуальные проверки фронтенда сохраняются: такие задачи получают `blocked`,
а цикл переходит к следующей подходящей задаче. Автономность цикла
не означает, что все задачи фазы могут быть завершены в этой песочнице.

Для `blocked` изменения сохраняются через stash с untracked-файлами;
его hash записывается в лог и комментарий issue. Перед назначением метки
`blocked` раннер создаёт её, если она отсутствует в репозитории; существующую
метку не изменяет. Для восстановления
переключись на оставшуюся ветку задачи и выполни указанную в комментарии
команду `git stash apply <hash>`. При повторном запуске раннер переключается
на существующую локальную ветку `issue-N`, сохраняя её коммиты. Если ветки
ещё нет, создаёт её от ветки фазы. Рабочая копия перед запуском должна быть чистой.

При `failed`, повреждённом отчёте или второй красной проверке изменения
остаются на ветке задачи. Проверь артефакты и комментарий перед продолжением.
Ошибки Git/GitHub останавливают запуск без автоматического отката:
если push прошёл, а закрытие issue не удалось, сначала сверяй состояние
веток и задачи. Уже существующий PR повторно не создаётся.
