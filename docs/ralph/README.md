# Ralph Loop

Раннер выполняет последовательные GitHub issues выбранной фазы. Требуется
Node 22.18+ (проверено на 22.19), git, gh с авторизацией, Codex CLI, Go
и окружение для команд проверок, включая Docker для `make test`.

Перед запуском закоммить изменения инструментов и убедись, что рабочая копия
чистая. Настройки находятся в `tools/ralph/ralph.config.json`:
`{phase}` подставляется в метку и ветку; проверки задаются массивами аргументов,
без shell-интерпретации. Значения по умолчанию: `phase-2`, `ralph/phase-2`
для фазы 2; remote — `origin`, базовая ветка — `main`.

```sh
node tools/ralph/ralph.ts --phase 2 --dry-run
node tools/ralph/ralph.ts --phase 2 --max-iterations 10
make ralph PHASE=2
node --test tools/ralph/*.test.ts
```

Dry-run читает Git и GitHub, показывает задачу и условный план команд,
включая `codex exec ... resume <thread_id> -`, не создаёт файлов и не запускает
агента. `maxIterations` считается по задачам: возвраты на исправление
не расходуют дополнительных итераций. Обязательный `maxFixAttempts` — целое
положительное число, по умолчанию 3: первый запуск и до трёх возвратов.
При достижении лимита с оставшимися подходящими задачами PR не создаётся.
При отсутствии подходящих задач PR может содержать частичную фазу;
заблокированные задачи остаются открытыми. Без коммитов относительно main
создание PR пропускается.

Артефакты: `.ralph/runs/<timestamp>-<pid>/run.log` и подкаталоги `issue-N/`:
`prompt-N.md`, `events-N.jsonl`, `report-N.json`, `agent-N.log`, `check-N.log`,
`report.schema.json`. Номер N начинается с 1 и увеличивается при каждом
вызове Codex, включая неудачный resume и запасной запуск. Файлы не перезаписываются.
`check-N.log` содержит внешние проверки и вывод коммита этой попытки;
при ошибке агента или `blocked`/`failed` он пустой. `run.log` содержит для каждого
вызова номер, thread_id и исход проверки либо причину её пропуска.
Журнал знаний `progress.md` находится под Git и коммитится вместе с задачей.

При красной проверке или ошибке коммита (включая lefthook) раннер продолжает
ту же сессию Codex. ID берётся из первого корректного события `thread.started`
в JSONL. Промпт `tools/ralph/ralph-fix.md` получает номер задачи и последние
80 строк `check-N.log` неудачной попытки. После ответа повторяются проверки
и коммит. При каждом resume явно передаются sandbox, Go-кэш и параметры
JSON-отчёта перед подкомандой `resume`; `--ephemeral` не используется.

Если ID отсутствует или команда resume завершилась ошибкой, раннер записывает
причину в `run.log` и один раз запускает Codex с нуля с полным заданием и логом.
Это тот же возврат в рамках `maxFixAttempts`; ошибка запасного запуска
останавливает цикл без рекурсивных повторов. Следующий возврат продолжает новую
сессию. Повреждённый JSON-отчёт останавливает цикл; `blocked` и `failed` после
resume обрабатываются так же, как после первого запуска.

При конфликте слияния `issue-N` в ветку фазы раннер один раз запускает Codex
с отдельным заданием: объединить изменения обеих веток и исправить конфликтные
файлы. Артефакты этого запуска и повторных проверок сохраняются в `issue-N/merge/`.
Раннер добавляет разрешённые пути в индекс, проверяет отсутствие маркеров
конфликта и незавершённых конфликтов, повторяет все `checks` из конфигурации,
создаёт merge-коммит и выполняет push. Закрытие issue происходит после push.
Проверяется, что агент сохранил исходные HEAD, MERGE_HEAD и ветку фазы.
При ошибке агента, оставшемся конфликте или красных проверках цикл останавливается:
рабочая копия и незавершённое слияние остаются для разбора, issue остаётся открытым.
Другие ошибки merge (например, ошибка hook) не запускают Codex.

Агент работает неинтерактивно: решения и неоднозначности разрешает
самостоятельно по приоритетам источников из `implement`. Фиксирует допущения
и обоснования в журнале и отчете; отсутствие согласования не является блокером.
При объективной невозможности продолжить возвращает `blocked` с объяснением.
Скиллы подготовки PRD, исследования и планирования в цикле не вызываются.
По указанию пользователя предыдущие визуальные проверки приняты: повторный
визуальный проход и шаг 6 `implement` в цикле не требуются. Требования
повторного UX-ревью, Playwright и видео из `web/AGENTS.md` также не применяются
в этом режиме. Требование визуальной проверки в issue, `AGENTS.md` или
скилле не блокирует запуск Ralph и выполнение задачи. Агент сохраняет
критерии поведения продукта, запускает `make check` и указывает в отчете,
что новые браузерные проверки не проводились. `make test` выполняет раннер
снаружи песочницы. Другие объективные препятствия по-прежнему могут
заблокировать задачу.

Для `blocked` изменения сохраняются через stash с untracked-файлами;
его hash записывается в лог и комментарий issue. Перед назначением метки
`blocked` раннер создаёт её, если она отсутствует в репозитории; существующую
метку не изменяет. Для восстановления
переключись на оставшуюся ветку задачи и выполни указанную в комментарии
команду `git stash apply <hash>`. При повторном запуске раннер переключается
на существующую локальную ветку `issue-N`, сохраняя её коммиты. Если ветки
ещё нет, создаёт её от ветки фазы. Рабочая копия перед запуском должна быть чистой.

При `failed`, повреждённом отчёте или исчерпании `maxFixAttempts` изменения
остаются на ветке задачи. Проверь артефакты и комментарий перед продолжением.
Остальные ошибки Git/GitHub останавливают запуск без автоматического отката:
если push прошёл, а закрытие issue не удалось, сначала сверяй состояние
веток и задачи. Уже существующий PR повторно не создаётся.
