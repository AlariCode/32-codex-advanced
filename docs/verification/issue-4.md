## Порядок

Основные серверные тесты сначала прошли Red; после этого три файла
(`recovery_integration_test.go` в API и worker, `safehttp/retry_test.go`)
зафиксированы контрольными суммами в `tmp/issue-4-tdd.sha256`. UI: реализация, визуальный
проход 375×812 / 768×1024 / 1440×900, UX-ревью, затем новые Playwright-тесты.
При недоступном API UI сохраняет processing и сообщает о сбое обновления;
локальные часы не переводят карточку в failed без ответа сервера.

## TDD и дополнительные проверки

Red подтвердил функциональные пробелы: шесть путей API оставляли просроченную
карточку processing/queued; Claim не восстанавливал lease; heartbeat не продлевал
lease; HTTP 429/500/503 давали единственный запрос. Тестовые данные heartbeat
исправлены до фиксации тестов (обязательный user ID и 32-байтовый digest).
После фиксации эти тесты не менялись; контрольные суммы проверены повторно.

Дополнительно проверены fences продления (token/generation/state/оба deadline/
просроченная lease), ограничение ровно пятью HTTP-запросами, восстановление
после обрыва TCP и sweep накопившихся deadlines разных владельцев. Настоящий
Go-процесс worker убит SIGKILL после начала HTTP-загрузки; тест ждёт 46 секунд
без изменения SQL-времён и запускает новый процесс. Фактический результат:
executions=2, snapshots=1; старый token не продлевает lease и не публикует текст.
Отдельный конкурентный тест допускает одного из двух претендентов на reclaim
и отклоняет старую публикацию, пока актуальная generation ещё processing.

## Визуальная проверка и UX

Библиотека `/`: долгий processing и failed/timeout проверены в Chromium на
375×812, 768×1024, 1440×900. Переполнений/перекрытий нет; URL и причины
переносятся, действия доступны и сохраняют 44 px высоту. По ui-ux-pro-max
проверены обратная связь при долгом ожидании, понятная причина timeout,
доступность действий/форм, status region и сохранение фокуса. Дополнительных
визуальных исправлений не потребовалось. Снимки: `tmp/issue-4-{processing,failed}-{375,768,1440}.png`;
в PR изображения загружаются вложениями, локальные пути не служат ссылками для ревьюера.

Во всех строках матрицы фактический результат совпал с ожидаемым. Через 30 секунд
processing остался processing; после reload deadline/generation сохранились;
реальная задержка до исходного deadline завершилась timeout. При остановленном
worker API завершил queued, поздний старт не дал читалку. Retry-After 35 секунд
сохранил попытку, а после реального истечения сессии/закрытия страницы новый вход
тем же аккаунтом получил ready. Браузерный kill/reclaim завершился одним актуальным
результатом; SQL-проверки дополнительно отклонили старые token и generation.

Первый UI-прогон выявил неоднозначный новый locator `alert` из-за системного
announcer Next.js. Locator уточнён по тексту ошибки; assertions сохранены.
Существующие тесты не менялись. Итоговый полный прогон — 144/144.

Проверен 161 непустой WebM. Все восемь видео новых сценариев имеют положительную
длительность (ffprobe): три mock-разрешения и пять файлов реальных сценариев,
включая отдельное видео страницы после нового входа. Пути:

- `tmp/playwright/videos/waiting-server-age-survive-ce0eb-fline-never-invents-timeout-{mobile,tablet,desktop}/video.webm`
- `tmp/playwright/videos/integration/recovery-*/video*.webm`

Длительные реальные E2E выполняются на 1440×900; регрессия архива, visual/UX и
mock-проверка времени/offline покрывают все три разрешения. Восстановление после
полного отказа проверено точечно sweep накопившихся SQL deadlines; настоящий
процессный сценарий использует kill/restart worker и реальные 45/120 секунд.
Изображения/ручной retry и последующие фазы не заявляются готовыми.
