# Потоковый HTML и восстановление сессии

Проверка 21 октября 2026 года после ручной проверки фазы 2.

## Текст PurpleSchool

Проблемная ссылка: <https://purpleschool.ru/blog/claude-md-instrukcii-dlya-claude-code>.
Существующая карточка имела `unavailable / article_unavailable`, хотя публичный
ответ HTTP 200 содержал текст. React передавал статью в скрытом сегменте `S:3`
и завершал его статической инструкцией `$RC("B:3","S:3")`. Readability удалял
скрытый сегмент, поскольку перенос в соответствующую Suspense-границу не выполнялся.

Перед классификацией и извлечением восстанавливается только перенос завершённых
сегментов с однозначными ID, скрытым контейнером, статической инструкцией и парными
комментариями границы. Удаляется временный fallback; вложенные границы сохраняют
порядок. JavaScript источника не выполняется, hydration JSON не используется.
Неоконченные сегменты и остальные скрытые блоки остаются скрытыми. Проверки
доступа и ограничения дерева применяются после восстановления структуры.

Добавлены автономные регрессии: завершённая и вложенная границы, удаление fallback,
сохранение пробелов и языка кода, неоконченные и некорректные границы, дубли ID,
текст инструкции внутри строки JavaScript и форма доступа внутри статьи.
До исправления тест завершённого потока терял основной текст; после исправления
весь пакет extract проходит.

На полученном HTML отдельно проверены все **41 абзац по порядку, 7 h2 и 6 блоков
кода с точным совпадением содержимого** внутри исходного `.markdown`. Архив
содержит 59 блоков. Исходный HTML издателя не включён в репозиторий.

Новое сохранение через работающие локальные API, PostgreSQL и worker в отдельном
тестовом аккаунте: HTTP 201, затем `processing → ready` за 8,7 с. Начало, последний
раздел и заключение проверены через API документа. Это одно контрольное сохранение,
а не повтор benchmark #12. Предупреждения `images_omitted` и `text_incomplete`
остаются видимыми; результат не объявляется полным архивом изображений.

## Мигание интерфейса

Ранее события `focus`, `pageshow`, `online` и `visibilitychange` запускали полную
загрузку: очищали личные данные, введённый URL и черновики, прерывали запросы
сохранения и показывали гостевую навигацию до ответа проверки сессии.
Читалка аналогично размонтировала открытую статью.

Проверка при возврате во вкладку теперь выполняется в фоне с объединением
одновременных событий. При той же сессии сохраняются карточки, пагинация, форма,
черновики, фокус и запросы записи. Первичная проверка показывает нейтральное
состояние ожидания; гостевая навигация появляется после подтверждённого 401.
Настоящий 401 очищает личные данные и отменяет старые запросы. Смена ID пользователя
вызывает полную загрузку без переноса карточек предыдущего владельца.

Читалка сохраняет статью во время фонового запроса и временной сетевой ошибки,
но очищает её при потере доступа или недействительном документе.

Добавлены браузерные сценарии для первичной проверки, серии событий восстановления,
незавершённого POST, сохранения DOM и ввода, 401, смены аккаунта и фонового чтения
при успехе, сетевой ошибке и 401. Старый тест гостевой ссылки регистрации теперь
явно получает 401, вместо зависимости от недоступного API тестового прокси.

`make check` прошёл. Для HTTP-тестовых серверов использован запуск с разрешением
локальных сетевых портов; первый sandbox-запуск остановился на запрете bind.

Полный `npm run test:e2e` на окончательной версии: **210/210** за 3,7 минуты,
включая 21 новую проверку восстановления сессии на ширинах 375/768/1440.
Первый прогон остановлен после обнаружения двух проблем тестов: неявной зависимости
гостевой регистрации от отсутствующего API и неоднозначного `role=alert`, совпавшего
также с announcer Next.js. Гостевой ответ теперь явно замокан как 401, а проверка
ошибки читалки ограничена основным содержимым страницы.
