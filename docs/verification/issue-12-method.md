# Issue 12: методика приёмки архива

Команды выполняются **из корня репозитория**. Требуются Node ≥22, Go из go.work,
зависимости `npm ci` / `npm ci --prefix web`, установленный Playwright Chromium,
Docker и доступ в публичный интернет. Нужны свободные локальные порты.

```sh
npm run benchmark:archive -- --output tmp/archive-benchmark-2026-10-21
npm run benchmark:recalculate -- tmp/archive-benchmark-2026-10-21/runs.jsonl
```

Каталог результата должен отсутствовать: команда не перезаписывает прошлые
измерения. Без `--output` создаётся новый каталог под `tmp/archive-benchmark/`.
Exit 0 означает, что команда завершила сбор свидетельств, **а не достижение
скорости**: проверять `summary.targetMet` и фактическое число из 60.

## Изоляция и постоянные условия

Команда запускает тестовый PostgreSQL через compose.test.yaml; принимает только
локальный TEST_DATABASE_URL с БД linkbook_test. В ней создаётся отдельная схема
e2e_benchmark_*, удаляемая после завершения. Рабочая БД не используется.
Результаты экспортируются до удаления схемы. При SIGINT сохраняются уже
записанные строки и промежуточный отчёт; незавершённый набор не объявляется 60
измерениями. SIGKILL может потребовать ручной очистки только своей схемы.

Перед каждым запуском выполняются make build и сборка штатного integration-db
helper. API_ORIGIN фиксируется до production-сборки Next. Запускаются настоящие
API и **production worker с safehttp.New**, без fixture-origin или подмены
извлечения. Это host-процессы, не контейнер worker с firewall: ограничение
явно записано в environment.json. Worker обрабатывает одну задачу за раз,
GOMAXPROCS=1, GOMEMLIMIT=384MiB; API GOMAXPROCS=2. Это лимиты runtime,
не гарантированная квота CPU/RAM операционной системы.

Chromium headless, одна страница, 1440×900, без throttling и service workers.
UI использует штатный polling каждые две секунды. Никакие другие тесты не
следует запускать параллельно измерениям. Фоновая нагрузка машины и CDN/cache
не контролируются; начальная load average и load до/после каждой попытки
сохраняются. Тип физического подключения/VPN не инструментируется и не
выдаётся за известный. Версии ОС, CPU/RAM, Go, Node, Chromium, Next,
PostgreSQL, Readeck, commit, dirty files и SHA-256 команды/корпуса записываются.

## Корпус, новые сохранения и время

Фиксированный corpus.mjs копирует шесть URL из утверждённого исследования:
go-strings, go-pipelines, MDN Introduction, Cloudflare Pingora, Habr GC,
Habr Avito. Для каждого — десять сохранений подряд, затем следующий источник;
всего 60. Корпус не выбирается по результатам. Query/cache-buster к URL не
добавляются. На каждую попытку создаётся независимый аккаунт с новой сессией.
Пароли и cookies не пишутся в отчёт. Создание аккаунта и загрузка библиотеки
выполняются до отсчёта; сохранение отправляет обычная кнопка UI.

Начало — серверный requested_at, установленный непосредственно перед commit
сохранения, подтверждённый HTTP 201 и created=true. Время подтверждения
server_time и получения ответа браузером также сохраняется. Конец — первая
DOM-мутация карточки «Готово» с доступной ссылкой на читалку, зафиксированная
MutationObserver с performance.timeOrigin+performance.now. API и браузер
работают на одной машине; PostgreSQL находится в Docker VM. Методика
предполагает синхронизацию VM/хоста и общий epoch без скачка часов. Отдельная
калибровка clock offset не выполняется; разницы server_time/requested_at и
получения ACK сохранены для проверки этого допущения. RFC3339 timestamp округляется до миллисекунд Date.parse;
погрешность начала менее 1 ms плюс планирование callback наблюдателя.
Это консервативно включает короткий SQL-хвост до commit, доставку ответа,
очередь, HTML/media, извлечение, публикацию и polling. Не заменяется временем
парсера или первым GET статуса. Hidden-страница не засчитывается успешной.

После фиксации времени проверяются приватный document, отсутствие pending
media, пригодность текста реальному renderer и HTTP 200/тип/байты всех
уникальных архивных image assets. У каждой image-позиции есть asset_id либо
явная omission-причина; при пропусках требуется images_omitted. По Q03
частичный результат с явным предупреждением допускается, его расхождения
всё равно отражаются в отдельной оценке качества. Проверочная загрузка
документа/media после наблюдения не прибавляется к измерению; при её провале
попытка исключается из успехов. URL оригинальных изображений не загружается
читалкой как fallback.

Дубликат, generation≠1, unavailable, failed, неподтверждённое сохранение,
непригодный документ или незавершённое media — не успешная обычная статья.
При потере подтверждения попытка не повторяется скрыто: остаётся неудачей.
readyWithin15s требует elapsedMS ≤15000; знаменатель всегда 60, порог 54.
P50/P90 nearest-rank описывают только пригодные ready и подписаны как условные.
Неудачи и отсутствие строк не исчезают из знаменателя.

## Артефакты и независимый пересчёт

- runs.jsonl: одна неизменяемая строка каждой попытки, включая ошибки, ID
  аккаунта/карточки, generation, исходные времена и load.
- report.json / report.md: все попытки, сводка по статье, порог и явный MET/
  NOT MET. Промежуточный отчёт обновляется после каждой строки.
- environment.json и services.log: условия и stdout/stderr процессов.
- artifacts/: документы, screenshots и source snapshots с HTTP-статусом,
  final URL и SHA-256. Исходник забирается **после** десяти измерений источника.
  Это отдельный запрос: изменяемая страница может отличаться от HTML worker;
  такие изменения нужно описывать, а не считать потерей извлечения.

Сырые HTML и полные тексты не коммитятся. Для долговременного отчёта сохраняются
метаданные, все 60 строк и конкретные расхождения, без копии чужих статей.
recalculate читает только JSONL, заново вычисляет elapsedMS и агрегацию,
отвергает дубликаты измерений/аккаунтов и изменение корпуса. Детерминированные
тесты границы 15 s, порога, ошибок и агрегации входят в make check:

```sh
node --test scripts/archive-benchmark/metrics.test.mjs
```

Живой benchmark **не включён** в make check, make test и обычный Playwright.

## Ручная сверка качества и регрессия

Для каждого источника открыть source snapshot/оригинал и реальную читалку,
прочитать весь основной материал по порядку, сверить каждый смысловой
заголовок, абзацы, списки, цитаты, видимый код, таблицы, изображения и подписи.
Скрытый scaffolding playground, навигация, формы, related posts и комментарии
читателей не относятся к основному материалу. Сопоставление нормализованного
текста и точных code blocks помогает найти кандидатов расхождений, но
**не заменяет** ручной просмотр, оценку смысла или проверку изображений.
В отчёте отделяются реальные потери, намеренные исключения, предупреждения
и невозможность сверки. Отсутствующие в источнике типы блоков отмечаются N/A.

Общая регрессия фазы выполняется отдельно, после живых измерений:

```sh
make check
make test
npm run test:e2e
npm run test:e2e:integration
make build
make openapi
```

Playwright-конфигурации включают 375/768/1440 px и video:on. Оба набора
собирают production Next с соответствующим API_ORIGIN и запускают next start;
HMR/компиляция dev-сервера не влияют на UI-таймеры. На старт сборки выделено
120 секунд; таймауты действий/assertions и продуктовые 30/120 секунд не менялись. Непройденные
проверки/цель 54/60 явно остаются непройденными. PRD, план, корпус и лимиты
ради замеров не меняются; исправление причины должно оставаться в принятых
границах архитектуры.
