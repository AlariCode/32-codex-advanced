# #12 — Приёмка качества и скорости архива

Дата: **2026-10-21**. [Методика и команды](issue-12-method.md).
Корпус, PRD, план и принятые лимиты не менялись.

**Цель скорости не достигнута: 49/60 при требуемых 54/60.**
Это результат полного повторного замера после исправлений качества.
Все 60 сохранений новые, все 60 завершились пригодным ready; частичный
результат Cloudflare с явными пропусками media учитывается по принятому Q03.
Достижение цели всей фичи или завершение приёмки скорости не заявляется.

## Измерения и условия

Исходная серия была диагностической: параллельно выполнялись разработка
и узкие unit-регрессии, поэтому причинное сравнение скорости с итоговой
серией не проводится. Итоговые 60 сохранений выполнялись отдельно от
регрессионных тестов.

Исходный замер: 08:28:10–08:40:01 UTC, 60 подтверждённых новых сохранений,
59 ready, **48/60 ≤15 s**. Habr Avito, попытка 8, завершилась failed/timeout
через 120443.5 ms. Все результаты, включая этот провал и медленные попытки,
сохранены в [baseline/runs.jsonl](issue-12/baseline/runs.jsonl).

После двух исправлений извлечения выполнены **ещё 60 новых сохранений**,
08:41:45–08:52:14 UTC. Результаты двух запусков не смешиваются и лучшие
попытки из них не отбираются. Итоговый знаменатель — второй полный набор 60:

PostgreSQL timestamp находится в часовом домене Docker VM; предполагается
синхронизация с хостом. Проверка исходных времён второго набора: API ACK минус

Среда: macOS Darwin 27.0.0 / arm64, Apple M1 Pro, 8 логических CPU, 16 GiB
RAM; Node 24.21.0, Go 1.27.2, Chromium 153.0.8010.12, Next 16.3.8,
Readeck 2.1.3, PostgreSQL 18.6 (Docker). API и production worker — host-процессы;
worker concurrency=1, GOMAXPROCS=1, GOMEMLIMIT=384MiB, API GOMAXPROCS=2.
Сохранения строго последовательны, отдельный аккаунт/контекст на каждое,
UI 1440×900 и штатный polling 2 s. Сборка production Next, часы API/браузера
на одном хосте. Замер включает очередь, HTML/media, обработку, commit и
появление ready в DOM; пригодность документа и media подтверждается после
фиксации времени. Регрессия выполнялась после benchmark.

Начальная load average: 57.20/70.39/67.81 и 61.25/57.53/59.77, свободной
RAM примерно 160 и 144 MiB соответственно. Это **нагруженная общая машина**,
не выделенный performance-стенд. Нагрузка до/после каждой попытки сохранена.
Публичный интернет без заданного throttling; тип подключения/VPN не
инструментировался, DNS/CDN cache не контролировались, URL не менялись.
Нельзя переносить эти числа на весь интернет или выводить причинность из
разницы двух запусков. Полные условия:
[baseline/environment.json](issue-12/baseline/environment.json) и
[final/environment.json](issue-12/final/environment.json).

В worker media загружается последовательно. Корреляция медленных результатов
с 25 изображениями Avito согласуется с затратами на сеть/media, но отдельные
стадии не инструментированы: это вероятный вклад, не доказанная единственная
причина. Архитектура, concurrency загрузок, дедлайны и лимиты ради порога не
менялись. **Критерий 54/60 остаётся невыполненным.**

Конкретные расхождения и решения:

- **go-pipelines:** в исходном архиве из 17 code blocks пропали выделенные
  `span.comment` комментарии, в том числе пояснения ожидаемых результатов.
  Readeck принимал их за обсуждение страницы. Теперь видимые pre защищаются
  существующим механизмом placeholders до выбора основного материала,
  затем возвращается исходный текст без исполнения markup. Все 26 блоков
  повторного архива совпали посимвольно с исходными и в исходном порядке.
  Скрытый playground scaffolding не возвращается в статью. Отдельный тест
  подтвердил RED до исправления и GREEN после; прежние тесты кода не ослаблены.
- **Habr GC:** исходный архив терял первый h2 «Стек и куча в Go» при сохранных
  соседних абзацах. Теперь защищаются смысловые заголовки h1–h6, пережившие
  выбор статьи; все 12 подзаголовков повторного архива присутствуют. Для этого
  случая также подтверждён RED/GREEN на синтетической регрессии.
- **MDN:** таблица сохранена как таблица, обе колонки и все восемь ячеек
  совпали; первоначальная текстовая проверка целого table дала несовпадение
  только из-за границ ячеек. В конце сохранились две ссылки Previous/Next:
  это навигационный остаток, не основной текст. Оценка не объявляет их частью
  содержательного результата. Global navigation, поиск и feedback-форма в
  renderer не выданы как статья; весь основной текст до конца присутствует.
- **Cloudflare:** на дату проверки оригинал отдаёт содержательные картинки
  через URL с `f=webp`. Текущие проверяемые кодеки — PNG/JPEG/GIF; две картинки
  дают image_invalid. Ещё две aria-hidden data:SVG заглушки попали в архив как
  image_source_unsupported. Таким образом, отображаются четыре явных пропуска
  вместо двух изображений. Это реальная неполнота и лишние placeholders,
  а не полный архив изображений. images_omitted показан, внешнего fallback
  или незаявленного получения оригинального PNG не добавлено.
- **Habr GC/Avito и MDN:** 13, 25 и 1 архивных файла просмотрены и сопоставлены
  с source URL + байтами по принятому asset-ID hash. Все 39 соответствуют
  исходным позициям; приватные HTTP-ответы 200, MIME и ненулевые bytes проверены.
  Подписи GC сохранены целиком. В Avito сохранены схемы разметки/очистки,
  список и цитата, концовка и редакционная ссылка на предыдущую статью.
- **go-strings:** все 21 видимых code block, escape-последовательности и
  Unicode сохранены точно. Скрытые copyright/package-префиксы playground,
  интерактивные кнопки и глобальная навигация не являются основным текстом.
- У проверенных архивов сохраняется text_incomplete; Habr также имеет
  images_omitted при сохранных содержательных image-позициях. Эти предупреждения
  не отключались ради отчёта. Для проверенных основных блоков соответствующих
  дополнительных потерь не найдено; отсутствие/наличие warning не является
  универсальным доказательством полноты произвольной страницы. В Habr до
  текста остаются метаданные сложности/времени чтения — не меню или форма.

Качество и скорость оценены отдельно. Частичный Cloudflare не назван полным;
ограничения статического пути, кодеков и предупреждений сохранены. Формы,
скрипты и рекламные элементы не становятся исполняемым содержимым renderer.
Полные HTML/документы/screenshots находятся локально в
`tmp/issue-12-{live,final}/artifacts/` и не коммитятся.

## Воспроизведение и соответствие критериям

Команды находятся в [методике](issue-12-method.md), включая независимый
пересчёт всех строк. Обычный make check включает только детерминированную
проверку времени/агрегации. Живой интернет запускается исключительно явно.
Обе схемы benchmark удалены после экспорта, рабочая БД не использовалась.

Измерения привязаны к base commit 2ac6039 и dirty workspace, а не выданы за
измерения ещё не существовавшего финального коммита. Сохранены SHA-256 driver,
корпуса, бинарников и для второго запуска manifest исходников backend:
[backend-source-sha256.json](issue-12/final/backend-source-sha256.json).
Последующие изменения документации/регрессионного harness не меняют измеренный
продуктовый код. Public sources меняются; даты и hashes отдельных source
snapshots сохранены в каждом каталоге результатов.

- Качество корпуса сверено целиком; конкретные потери и оставшиеся ограничения
  приведены выше, совершенство извлечения не заявляется.
- Команда, методика и детерминированные тесты добавлены.
- Во втором наборе 60 подтверждённых новых сохранений / 60 разных аккаунтов;
  исходные URL неизменны. Обе полные серии опубликованы без отбора.
- Отсчёт до отображения ready включает очередь и media; document/assets
  дополнительно проверены. Все неудачи исходного набора сохранены.
- Условия, версии, concurrency, resources и известные сетевые ограничения
  записаны. Это последовательные измерения, не concurrency-тест.
- **54/60 не достигнуто — невыполненная цель скорости.**
- Общая регрессия фазы **прошла**: make check, make test, make build,
  make openapi завершились с кодом 0; единый npm run test:e2e — **189/189**,
  npm run test:e2e:integration — **73/73**. Все 24 сквозных retry прошли на
  375/768/1440 px; все четыре recovery с реальными таймерами прошли.
  Созданы 83 непустых integration-видео, включая 24 retry, в
  tmp/playwright/videos/integration/. Это также завершает ранее нестабильную
  браузерную проверку зависимости #11.
