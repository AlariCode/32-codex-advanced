# Контракт безопасного архива изображений

Документ v2 расширен узлами `image`, `figure`, `figcaption`; v1 продолжает
читаться без миграции. `image` содержит alt и ровно одно из `asset_id` или
`omission`. Временный `Source` существует только в памяти worker и не попадает
в JSON или PostgreSQL. Изображения и figure защищены от преобразований Readeck
маркерами до отбора статьи, затем возвращаются на выбранное место.

Поддерживаются абсолютные и относительные HTTP(S) src, srcset и lazy-атрибуты.
На исходную позицию сохраняется один доступный вариант, с учётом final URL и
первого base[href]; каждый кандидат независимо проходит прежнюю сетевую защиту.
Порядок выбора, бюджеты альтернатив и предупреждения частичного текста
описаны в [проверке #10](issue-10.md). Подписи и alt не теряются при ошибке изображения. В браузере
нет URL оригинального изображения, fallback и Next Image Optimizer/cache;
используется исключительно приватный same-origin маршрут assets.

## Кодеки и технические пределы

- PNG (`image/png`), JPEG (`image/jpeg`), статический GIF (`image/gif`).
  Корпус `web/tests/fixtures/images/archive.{png,jpeg,gif}` — собственная
  иллюстрация 320×180, сохранённая в трёх настоящих растровых форматах.
  `TestCommittedImageCorpus` декодирует каждый файл; интеграционный браузерный
  сценарий сравнивает bytes с этими же файлами, а не с сигнатурой-заглушкой.
  Это воспроизводимый локальный корпус; сетевой RU/EN-корпус исследования
  в этой итерации не скачивался и не проверялся.
- SVG, WebP, AVIF и прочие форматы отклоняются явно (`image_invalid`).
  Проверяется сигнатура стандартным Go DecodeConfig, затем полный Decode;
  MIME источника не считается доказательством формата. Проверенный MIME
  вычисляется по bytes, повторно проверяется при публикации и приватной выдаче.
- До полного decode: обе стороны 1–8192 px, произведение не более
  16 777 216 пикселей. Полный decode обязан совпасть с конфигурацией.
  Сжатый размер не заменяет предел выделяемых пикселей.
- Анимация не поддерживается: GIF block scanner без выделения кадров
  отклоняет второй image descriptor; каждый descriptor имеет отдельную
  проверку размеров/пикселей. Статический GIF дополнительно проходит DecodeAll.
  PNG с acTL (APNG) отклоняется до pixel allocation. Неограниченного
  DecodeAll на входной анимации нет.
- До 5 MiB включительно после HTTP-декомпрессии на ответ; читается максимум
  limit+1. Сохраняется до 20 MiB включительно и не более 50 позиций.
  Каждая позиция, включая неподдерживаемую, расходует лимит числа позиций;
  после исчерпания лимита новые HTTP-запросы не выполняются. В сумму входят
  bytes всех загруженных кандидатов, включая неудачные и повторные позиции
  (консервативно). Повторяющиеся asset IDs хранятся один раз в документе.
- Загрузка и decode последовательные, worker обрабатывает одну статью.
  HTTP-запрос ограничен 25 секундами и общим deadline попытки. Стандартный
  decoder не прерывается context посреди CPU-операции: размеры ограничивают
  работу, а SQL deadline независимо запрещает позднюю публикацию.
  Production compose уже ограничивает worker 512 MiB RAM/1 CPU/64 процесса
  и GOMEMLIMIT=384MiB. GOMEMLIMIT — цель GC, не жёсткий предел одной аллокации.
  Предел 16M даёт до 128 MiB pixel buffer RGBA64 плюс рабочую память decoder;
  общий RSS ограничивается контейнером, а не обещанием остановки CPU по context.

## Сеть, хранение и выдача

FetchImage и HTML используют один fetchOnce: запрет proxy/cookies,
проверка URL/всех DNS-ответов, публичного назначения, IP-pinned dial без
второго resolve, новый transport на каждый redirect, максимум 5 redirects,
TLS verification и прежняя egress-политика контейнера. Единственное исключение
loopback — отдельно собранный integration-worker с точным fixture origin;
перенаправления на другой порт этого исключения не получают.

Миграция 006 добавляет assets с составным FK к snapshot (link_id,generation),
ограничением MIME и bytes. Миграции 001–005 не менялись. Publish проверяет
валидность документа/bytes и точное соответствие assets ссылкам документа,
затем одной транзакцией записывает snapshot, assets, ready и completed.
Проверки generation, execution_token, lease, обоих deadlines и processing
повторяются при финальном UPDATE. Ошибка commit откатывает всё.

GET /api/links/{id}/assets/{asset_id} проверяет сессию, владельца, актуальную
ready generation и ссылку в валидном опубликованном документе. Строка assets
сама по себе доступа не даёт. Чужой, неопубликованный или неупомянутый asset —
404; без сессии — 401. Ответ: проверенный MIME, nosniff, no-store и sandbox CSP.
Same-origin proxy поддерживает маршрут; reader CSP имеет img-src 'self',
connect-src 'self', object-src/frame-src 'none' и совместимые с текущим Next
script/style directives. Произвольные props, HTML и исходные обработчики
событий в renderer не передаются.

## Результаты этой итерации

RED подтверждён первым make check: отсутствовали новые поля/функции.
Зафиксированные assertions TDD не ослаблялись. Доступный make check прошёл:
Go unit tests/vet, ESLint и TypeScript. Первоначальный sandbox запрещал
httptest bind; повтор с разрешением локальных портов прошёл.

SQL-тесты и новые e2e добавлены для внешнего запуска. Браузерные сценарии
покрывают отключение источника/reload, bytes/MIME, чужой аккаунт, все три
предела отдельно, повреждённый и неподдерживаемый payload, blocked redirect,
отсутствие внешних запросов статьи и исполнения XSS. Конфигурация уже задаёт
375/768/1440 и video:on. Их выполнение и наличие новых видео НЕ проверялись.
Предыдущие визуальные проверки приняты по указанию пользователя; новых
браузерных проверок, UX-прохода и Playwright в этой итерации не было.
make test, make build и make openapi не запускались по ограничениям запуска.
OpenAPI JSON/YAML/Go и встроенная схема ReDoc обновлены локально без генератора
с сетевыми загрузками. При установленном Next нет каталога dist/docs;
использованы существующие настройки headers/rewrites и типы установленной версии.
