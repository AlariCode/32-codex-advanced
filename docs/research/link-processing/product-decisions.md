# Продуктовые решения по обработке ссылок

Дата: 2026-10-09. Основание: явные ответы пользователя на вопросы исследования [PRD](../../prd/link-processing.md). Статус решений Q01, Q03–Q07 и цели скорости Q02: **Принято**. В [техническом отчёте](README.md) также принят вариант очереди 11A без River; остальные технические варианты пока предложены.

| ID  | Исходный вопрос                                                                     | Выбранное поведение                                                                                                                 | Последствия                                                                                                                                                                                                                                                                                               |
| --- | ----------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Q01 | Как отличать отсутствие доступной статьи от ошибки извлечения?                      | Если страница загрузилась, но извлечь статью не удалось, сохранять ссылку без читалки с возможностью повторить обработку.           | Отсутствие извлечённого текста само по себе не является сетевой или системной ошибкой. Для этого результата нужны «Повторить», «Открыть оригинал», «Удалить». Причины вроде недоступной сети, внутренней ошибки и превышения срока остаются ошибками обработки.                                           |
| Q02 | На каких статьях проверять качество и скорость?                                     | Пользователь поручил исследователю самостоятельно подобрать статьи.                                                                 | Подобран корпус в [результатах экспериментов](experiments.md). Дополнительным ответом 2026-10-09 принята цель: 90% обычных статей готовы за 15 секунд. Методика измерения и критерии полноты ещё требуют уточнения; достижение цели не проверено.                                                         |
| Q03 | Что происходит при частичном результате?                                            | Готовая статья допустима даже с неполным текстом, если есть предупреждение.                                                         | При обнаруженной неполноте показывать предупреждение. Пропущенные изображения отмечать. Способ запасного заголовка ещё не выбран: предложение — метаданные страницы, затем hostname. Автоматически установить любую потерю текста невозможно; нельзя обещать полноту только по отсутствию предупреждения. |
| Q04 | Сколько может продолжаться длительная обработка?                                    | Через 2 минуты завершать попытку ошибкой с возможностью повторить.                                                                  | Через 30 секунд сохраняется согласованное сообщение о длительном ожидании. Общий предел ожидания принят 2026-10-09: 120 секунд от подтверждённого сохранения/ручного повтора, включая очередь и внутренние ретраи.                                                                                        |
| Q05 | Как ведёт себя предварительная карточка при закрытии страницы и повторной отправке? | Хранить черновик локально; повторная отправка возвращает существующую карточку; исправленный дубликат открывает её.                 | Черновик не равен сохранённой ссылке. При неизвестном результате отправки сервер должен вернуть единственную существующую карточку владельца. Нужны привязка локального черновика к аккаунту и предотвращение показа черновиков другого пользователя на общем устройстве.                                 |
| Q06 | Как обрабатываются удаление и истечение сессии?                                     | Подтверждение удаления, без восстановления; удаление отменяет обработку; при истечении сессии вход с возвратом на прежнюю страницу. | Только после успешного удаления карточка исчезает; при ошибке остаётся и позволяет повторить. После удаления worker не вправе публиковать результат. Возврат после входа проверяет, что статья ещё существует и принадлежит вошедшему пользователю.                                                       |
| Q07 | Как отображаются ошибки загрузки списка и читалки?                                  | Сообщение и кнопка «Повторить», уже загруженное содержимое сохраняется, если оно есть.                                              | При первой загрузке нужен экран ошибки с повтором. При потере авторизации сохранённый UI не должен продолжать показывать личные данные другому аккаунту; восстановление после входа требует новой проверки доступа.                                                                                       |

## Дополнительно принято 2026-10-09

- Собственная очередь на PostgreSQL, без River: [решение Q11](README.md#q11-как-обеспечить-надёжную-фоновую-обработку-и-обновление-карточек).
- HTML до **3 MiB после декомпрессии**.
- Одно изображение до **5 MiB**, суммарно изображения до **20 MiB**, не более **50 изображений** на статью.
- При пропусках из-за лимитов — частичный результат с предупреждением.

## Что ещё требует выбора

1. Технические варианты Q08–Q10, Q12–Q13 и способ обновления UI Q11 в [отчёте](README.md). Выбор очереди не означает принятия остальных предложений.
2. Методика проверки принятой цели скорости и критерии полноты по подобранному корпусу; сам факт извлечения не доказывает полноту.
3. Способ запасного заголовка и прочие детали, которые пользователь явно ещё не выбирал.

Реализация этими ответами не поручена.
