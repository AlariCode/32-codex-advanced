## Q08: извлечение

Гипотеза: поддерживаемый Go-преемник сохраняет основной текст, форматирование и image-узлы на характерном RU/EN корпусе без browser-runtime. Альтернатива — Mozilla Readability с полноценным HTML DOM.

Финальные версии: Readeck v2.1.3, bluemonday v1.0.27, x/net v0.58.0, x/text v0.42.0; Mozilla Readability 0.6.0, jsdom 27.4.0. Точные транзитивные версии зафиксированы в локальных manifests/lockfiles прототипов. Первые прогоны автоматически выбрали x/net v0.41.0; после проверки актуальности зависимостей повторили с v0.58.0 проекта. Таблица ниже относится к последнему Go-прогону. Начальные попытки с `JSDOMParser` Mozilla не подошли для обычного HTML; финальная успешная проверка использует jsdom с отключёнными по умолчанию scripts/resources.

Качество шести реальных извлечений пока проверено по наличию текста и DOM-структуры, а не полнотой всех абзацев. В Go-result остались SVG в некоторых страницах: extraction не является очисткой безопасности. Количество img не доказывает, что все изображения статьи сохранены, или что картинки вообще доступны для скачивания.

Предлагаемый корпус приёмки: эти шесть позитивных страниц; три публичных отрицательных примера; собственные fixtures JS-only/login/пустой HTML/redirect/частичная загрузка/битая картинка. Перед приёмкой вручную сверять начало, середину и конец статьи, все смысловые заголовки и image captions. Предложение: отсутствие меню/рекламы, сохранение основного смысла и предупреждение о выявленных потерях; цель 90% обычных статей за 15 секунд принята пользователем 2026-10-09; методика измерения и критерии полноты ещё требуют уточнения.

## Q09: представление

Гипотеза 1: очистка активного HTML сама по себе не делает архив изображений независимым. В Q08-проверке bluemonday v1.0.27 удалил onclick, script, javascript href, onerror, svg и iframe из конкретного payload, но оставил `img src="https://evil.example/tracker"`. Assertions прошли. Значит, перед выдачей требуется отдельная загрузка/переписывание ресурсов.

Гипотеза 2: можно передавать разрешённую структуру без активных элементов/атрибутов и внешних image URL. Q09 с x/net v0.58.0 дал JSON с `p`, текстовыми узлами, безопасным `https` href и `asset_id: "asset-1"`; активные nodes/attrs не попали в документ. Исходный image URL остался отдельным кандидатом для защищённой загрузки. Assertions прошли.

```sh
# Из корня проекта, при наличии локальных прототипов:
cd docs/tmp/research/link-processing/q09
GOWORK=off GOMODCACHE="$PWD/../gomodcache" GOCACHE="$PWD/../gocache" go mod download
GOWORK=off GOMODCACHE="$PWD/../gomodcache" GOCACHE="$PWD/../gocache" go run .
```

Ограничения: пример намеренно небольшой; не включает все элементы будущей схемы, alt/size, разрешение относительных href, лимиты глубины, real image decoder или React renderer. Декодирование image bytes, восстановление архива при недоступном оригинале, браузерное XSS-тестирование и полноценная sanitizer policy не запускались. Безопасность против произвольного payload этим экспериментом не доказана.

## Q10: сетевые ограничения

Гипотезы: проверять адрес назначения каждого redirect; IPv4-mapped IPv6 не должен обходить loopback block; resolve-once/pin исключает второй DNS lookup; превышение размера после gzip можно обнаружить.

Стандартная библиотека Go 1.26.5, сторонних зависимостей нет. Запуск:

```sh
# Из корня, при наличии локального прототипа:
GOWORK=off GOCACHE="$PWD/docs/tmp/research/link-processing/gocache" go run ./docs/tmp/research/link-processing/q10/*.go
```

Фактически: loopback v4/v6/mapped, private, metadata `169.254.169.254`, CGNAT и multicast отклонены, публичный пример разрешён. Mock RoundTripper вернул redirect на loopback; `CheckRedirect` остановил второй запрос (calls=1). Модель resolve/dial зафиксировала публичный IP и единственный вызов resolver. Распакованные 4096 bytes при пороге 1024 прочитаны через limit+1 как 1025 — превышение обнаружено. `net/url` принимает userinfo, следовательно его надо запрещать отдельно. Все assertions прошли.

Ограничения: mock-транспорт, а не живые DNS/HTTP соединения; диапазоны в примере намеренно неполные и не являются production IANA policy. Не проверены реальные TCP/TLS pinning, rebinding, proxy, HTTP/2 reuse/coalescing, IPv6 transition ranges, hostile headers и сетевой firewall. В отчёте предложена более полная спецификация; этот код переносить в production как готовый safe fetcher нельзя.

## Q11 и Q12: проверка в PostgreSQL

Гипотеза: PostgreSQL primitives позволяют хранить единственный link владельца, восстановить просроченную lease и не записать устаревший/удалённый результат. Пример использует TEMP-таблицы внутри транзакции, окончание — ROLLBACK. Ожидаемые и фактические результаты совпали:

- Повторный `(user_id,url)` через `ON CONFLICT` создал 0 новых строк.
- После generation change stale UPDATE записал 0 строк.
- Просроченный job был повторно захвачен через `FOR UPDATE SKIP LOCKED` и получил актуальную generation.
- DELETE другого владельца удалил 0 строк, исходная карточка сохранилась.
- DELETE владельца удалил карточку и каскадно job; последующий worker UPDATE записал 0 строк.
- Последняя проверка выдала `PASS: unique, owner filter, lease reclaim, stale fence, deletion cascade`, затем ROLLBACK.

```sh
# Из корня проекта:
docker compose -f compose.test.yaml up -d --wait postgres-test
docker exec -i linkbook-tests-postgres-test-1 psql -U linkbook_test -d linkbook_test < docs/tmp/research/link-processing/q11/probe.sql
```

Ограничения: последовательный SQL-сеанс, без настоящих параллельных worker, kill/restart, clock skew, starvation, session middleware и HTTP routes. В примере generation иллюстрирует fencing; для повторного исполнения той же generation нужен дополнительный execution_token, как предложено в Q11. River не установлен и end-to-end не запускался; совместимость `InsertTx(*sql.Tx)` подтверждена официальной документацией, интеграция с миграциями приложения остаётся следующей проверкой. Во время исследования тестовый контейнер поднят командой проекта и оставлен запущенным, как предусмотрено существующим тестовым workflow.
