# Дизайн-система Linkbook

Стиль основан на предоставленном референсе книжной библиотеки: тёплая бумага,
графитовый текст, спокойная типографика, много свободного пространства и тонкие
линии. Переносим этот характер в сервис сохранения и чтения статей. Композицию
книжного экрана, его боковую панель, обложку, отзывы и метаданные не воспроизводим.

## Статус и источник значений

Семантические токены живут в [web/src/app/globals.css](web/src/app/globals.css).
Общие компоненты в `web/src/shared/ui` используют их в кнопках, ссылках, полях,
уведомлениях, блоках подтверждения, формах и макетах аккаунта. Каталог
[/design](http://localhost:3000/design) доступен при запуске `npm run dev`.
В production маршрут возвращает HTTP 404. Каталог использует те же компоненты
и CSS-переменные, что и рабочие страницы.

Все рабочие страницы используют тёплую базовую поверхность, Inter и общие
роли заголовков. Гостевая главная, библиотека, профиль и читалка используют
общую шапку. На узком экране формы входа и регистрации стоят перед вступлением.
В читалке предупреждения собраны перед статьёй, а подсветка кода использует
отдельные `--color-code-*` на мягкой светлой подложке.

Цвета, размеры и радиусы восстановлены приблизительно по растровому референсу.
Для заголовков, UI и текста статьи выбран Inter Variable. Пакет
`@fontsource-variable/inter` подключает локальные WOFF2 с латиницей, кириллицей
и курсивом. Система описывает светлую тему.

Референс показывает мелкий текст примерно 12–14 px и крупный заголовок около
36–40 px. Для сайта базовый текст увеличен до 16 px, текст статьи — до 18 px.
Цвета ошибок, успеха и предупреждений, состояния элементов и размеры областей
нажатия добавлены для рабочих сценариев Linkbook: в референсе их нет.

## Контракт токенов

В `globals.css` два логических слоя в `:root`, без CSS `@layer`:

1. Базовые значения: `--palette-*`, семейства и числовые шкалы шрифтов,
   отступов, радиусов, размеров, теней и длительностей.
2. Семантические роли: `--color-*`, `--text-*`, `--font-ui`, `--gap-*`,
   `--padding-*`, `--radius-button` и другие имена по назначению.

В оформлении компонентов использовать семантические роли. Числовые значения
и базовую палитру менять в первом слое; назначение роли — во втором. Одинаковый
текущий цвет не делает роли взаимозаменяемыми: граница поля, разделитель и
вторичный текст решают разные задачи. Для новой повторяющейся роли сначала
добавить семантический токен. Не создавать локальные копии всей палитры.
Структурные CSS-значения (`grid`, `auto`, `100%`, `minmax(0, 1fr)`) остаются
в стилях компонентов. Значения системы хранятся в CSS, не дублируются в JS.

### Палитра и поверхности

| Роль               | Токен                                     | Назначение                                         |
| ------------------ | ----------------------------------------- | -------------------------------------------------- |
| Внешний фон        | `--color-bg-canvas`                       | Тёплый серый вокруг общей оболочки, если она нужна |
| Фон страницы       | `--color-bg-page`                         | Основная бумажная плоскость                        |
| Поверхность        | `--color-bg-surface`                      | Светлый контент, форма, диалог                     |
| Мягкая подложка    | `--color-bg-subtle`                       | Второстепенные области, код                        |
| Основной текст     | `--color-text-primary`                    | Заголовки и основной текст                         |
| Вторичный текст    | `--color-text-secondary`                  | Описания и метаданные                              |
| Приглушённый текст | `--color-text-muted`                      | Даты, подсказки, placeholder                       |
| Разделитель        | `--color-border-subtle`                   | Декоративное разделение областей                   |
| Граница контрола   | `--color-border-control`                  | Видимая граница поля и вторичной кнопки            |
| Основное действие  | `--color-action-primary`                  | Графитовая кнопка с `--color-text-on-action`       |
| Фокус              | `--color-focus-ring`                      | Контрастное внешнее кольцо                         |
| Статусы            | `--color-status-{success,warning,danger}` | Текст и значок состояния на соответствующей `*-bg` |

Основа палитры: почти белый `#fffef9`, бумажный `#f0eee2`, тёплый серый
`#ccc9bf`, графит `#292933`, основной текст `#17171c`. Полный набор и состояния
определены в CSS. Графит — основной акцент; не добавлять яркий брендовый цвет.
Цвета обложек или иллюстраций из референса не являются UI-палитрой.

Для обычного текста нужен контраст не ниже 4.5:1, для крупных заголовков и
значимых графических границ — 3:1. Слабый разделитель не заменяет границу
интерактивного поля. `--color-bg-canvas` не использовать как фон формы с
приглушённым текстом без отдельной проверки контраста. Статус всегда обозначать
также словами или значком: цвет не должен быть единственным сигналом.

### Типографика

Все размеры в `rem`, привязаны к пользовательскому размеру шрифта браузера.
Не фиксировать корневой размер в px и не уменьшать его для уплотнения интерфейса.

| Роль                        | Токен                  | Размер при корне 16 px | Вес / интерлиньяж |
| --------------------------- | ---------------------- | ---------------------- | ----------------- |
| Короткая подпись            | `--text-caption`       | 12 px                  | body / label      |
| Метаданные, label           | `--text-label`         | 14 px                  | label / label     |
| Основной UI-текст           | `--text-body`          | 16 px                  | body / body       |
| Текст статьи                | `--text-reading`       | 18 px                  | body / reading    |
| Заголовок карточки          | `--text-title-card`    | 20 px                  | label / label     |
| Заголовок раздела           | `--text-title-section` | 24 px                  | label / label     |
| Заголовок страницы          | `--text-title-page`    | 32–40 px               | heading / title   |
| Выделенный заголовок статьи | `--text-title-feature` | 32–48 px               | heading / title   |

В таблице веса используют `--weight-*`, интерлиньяж — `--leading-*`.
Крупные заголовки лёгкие (400), с `--tracking-title`. У обычного текста
`--tracking-body`. Полужирный 600 нужен для локального смыслового выделения;
не делать все заголовки жирными. Курсив допустим для короткой цитаты или лида,
не для длинного описания, подсказок или статуса ошибки. 12 px — только короткая
необязательная подпись; важную информацию и действия не уменьшать до этого размера.
Код и технические идентификаторы используют `--font-code`; обычные метаданные — UI-шрифт.

### Ритм, размеры и форма

Основа отступов — шаг 4 px; шкала: 0, 4, 8, 12, 16, 20, 24, 32, 40, 48,
64, 80, 96 px (соответствующие `--space-*` в rem). Связанные элементы стоят
ближе друг к другу, чем независимые группы. Для поля использовать `--gap-field`,
для вертикальной группы `--gap-stack`, для контентных блоков `--gap-content`,
между разделами `--gap-section`. Поля страницы адаптируются через `--gutter-page`
и `--padding-page-block`.

Ширина контента ограничена `--width-content`, формы — `--width-form`, строки
статьи — `--width-reading`. Это максимумы, не фиксированная ширина: контейнер
должен помещаться в доступный экран. Длинные URL и идентификаторы переносить.
Не превращать каждый фрагмент информации в отдельную карточку: группировать
его пробелом, заголовком и тонкой линией. Светлая поверхность должна оставаться
основным средством разделения, а не густая сетка рамок.

Карточки почти прямоугольные (`--radius-card`), панели и поля слегка скруглены
(`--radius-panel`, `--radius-input`). Кнопки имеют форму капсулы
(`--radius-button`), кнопки-значки и аватары — круглые. Не применять большой
радиус капсулы к контейнерам или карточкам статей.

Плоский контент использует `--shadow-surface`. `--shadow-floating` — для
всплывающего слоя. Более заметная `--shadow-cover` допустима у отдельной
иллюстрации, как тень обложки в референсе, но не у каждого списка или контрола.
Не добавлять стекло, размытый фон, декоративные градиенты или текстуру бумаги.

## Поведение и доступность при внедрении

- На область приходится одно визуально главное действие. Вторичные действия
  спокойнее; деструктивное действие использует отдельные danger-роли и понятный
  текст. Hover/active используют соответствующие токены, без сдвига геометрии.
- Высота обычного контрола — минимум `--height-control`, область нажатия
  значка — минимум `--size-touch-target`; между независимыми целями оставлять
  `--gap-inline`. Визуальный размер значка не равен размеру кнопки.
- Значки тонкие, контурные, из одного согласованного набора, без emoji и смеси
  заполненных и контурных стилей. У кнопок без текста обязательно доступное имя.
  Не подключать набор иконок до задачи на компоненты.
- Поля имеют постоянные label. Placeholder не заменяет label. Ошибка расположена
  у поля и связана с ним через `aria-describedby`; сохранять введённые данные.
  Loading, disabled, empty и error проектировать вместе с успешным состоянием.
  При загрузке сохранять доступное имя кнопки и объявлять занятость.
- Фокус показывать через `--width-focus-ring`, `--color-focus-ring` и
  `--offset-focus-ring`. Не убирать outline без замены. Hover не заменяет
  клавиатурное взаимодействие; ссылки в тексте должны распознаваться без цвета.
- Анимация только для обратной связи или появления слоя, с `--motion-*`.
  Эти токены обнуляются при `prefers-reduced-motion`; отдельные CSS-анимации
  также должны учитывать эту настройку. Не анимировать чтение и фон страницы.
- Адаптация следует содержимому: на узком экране сокращать колонки, переносить
  действия, сохранять порядок чтения и подписи. Не сжимать desktop-композицию
  целиком и не копировать навигацию из референса без продуктовой необходимости.

При применении системы проверить реальные страницы на 375×812, 768×1024 и
1440×900, длинный русский текст, масштабирование 200%, клавиатурный фокус,
основные состояния и reduced motion. Визуальное и UX-ревью, Playwright и видео
выполнять по [web/AGENTS.md](web/AGENTS.md). Проверки каталога запускаются
командой `npm run test:e2e:design`. Общий прогон `npm run test:e2e` проверяет,
что production возвращает 404.
